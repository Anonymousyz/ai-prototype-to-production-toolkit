# Production-ready AI thesis

This document turns the manifesto into a compact working model.

## The equation

```text
Production-ready AI = workflow + evidence + governance + accountability
```

| Component | Meaning | Failure mode if missing |
|---|---|---|
| Workflow | The system changes a real business process, not just a demo screen | No adoption, no owner, no measurable value |
| Evidence | Evaluation cases, logs, incidents, review records and pilot findings | Decisions are based on excitement, not proof |
| Governance | Data boundaries, risk register, controls, documentation and review gates | Unclear authorization, compliance gaps, weak control design |
| Accountability | Humans, teams and processes own review, incidents, cost and rollback | Everyone uses AI, nobody owns consequences |

## What this toolkit contributes

| Repository asset | Thought it operationalizes |
|---|---|
| Readiness checklist | Readiness is multi-dimensional, not just model performance |
| Scorecard | Deployment decisions need thresholds and veto items |
| Risk register | Risks must be named, owned and mitigated |
| AI system card | Teams should document purpose, data, limitations and controls |
| Model evaluation plan | Evaluation should be designed before production |
| Pilot review memo | A pilot should end with an explicit decision, not vague optimism |
| CLI report | Review outputs should be repeatable and shareable |

## How to use the thesis in a review

Use the thesis as a filter:

1. If there is no workflow owner, keep it as a demo.
2. If there is no evaluation evidence, keep it as a controlled pilot.
3. If there is no human responsibility chain, do not use it for high-impact decisions.
4. If there is no logging or rollback path, do not call it production-ready.
5. If costs and incidents have no owner, production readiness is incomplete.
